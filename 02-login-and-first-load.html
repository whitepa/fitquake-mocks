Round 2 · Login & First Load

Pick how the very first screens feel

This round shapes the login page, the loading/splash state, error display, password-recovery entry-point, and how a user picks which business they're working in. These are the very first surfaces a user sees, so they set the tone before any dashboard content loads.

Five dimensions, ~5 minutes. Your picks are saved in your browser as you go, so you can leave and come back. When you're done, hit Copy decision at the bottom.
1

Login page layout

The arrangement and visual weight of the login surface. Whatever we pick gets carried through sign-up, password-reset, and other unauthenticated screens for consistency.

2

Loading / splash state

What the user sees during the moment between "page loaded" and "session resolved + dashboard data ready." Typically 200–800 ms for returning users, longer on first cold start.

3

Login error display

Where the "wrong password" / "account locked" / "user not found" message appears. The pattern we pick here also becomes the default for other form errors throughout the app.

4

"Forgot password" placement

Where the password-recovery entry-point lives on the login form. Visible enough that a user can find it under stress, quiet enough not to compete with "Sign in."

5

Multi-tenant business switcher

Some staff/owners belong to more than one Fitquake business (e.g., a regional manager or a trainer working across two locations). Where do they pick which one they're working in? This decides the URL/header/redirect logic of the entire authed app.
